# AthleteIQ — Repository structure

> **Note:** This project uses `lib/` at the repo root and `functions/` as the
> single backend — see this document for path translations and backend layout.

This document records the **actual** layout of this repo so future prompts,
build-guide steps, and phase instructions use the right paths.

**Last verified:** 2026-08-14

---

## 1. Top-level tree

This is a **single-root Flutter project** — there is **no** `mobile/` subfolder.
Dart source lives at `lib/` directly under the repo root, alongside
`pubspec.yaml`, `android/`, `ios/`, and `web/`.

```
athleteiq/                          ← repo root = Flutter project root
├── lib/                            ← Flutter app (Dart)
│   ├── main.dart
│   ├── firebase_options.dart       ← generated by flutterfire configure
│   ├── dev/
│   │   └── widget_catalog.dart   ← debug widget gallery (Phase B)
│   ├── models/
│   ├── screens/
│   ├── services/
│   ├── theme/
│   │   ├── app_colors.dart
│   │   └── app_theme.dart
│   └── widgets/
├── test/
│   └── widget_test.dart
├── android/                        ← Flutter Android scaffold
├── ios/                            ← Flutter iOS scaffold
├── web/                            ← Flutter web scaffold
├── functions/                      ← Firebase Cloud Functions (TypeScript) ★ canonical backend
│   ├── src/
│   │   ├── index.ts                ← callable `recalculateRisk`
│   │   ├── calculations.ts
│   │   ├── riskModel.ts
│   │   ├── recommendationEngine.ts
│   │   └── aiChat.ts               ← Phase E2 Ask AthleteIQ stub
│   ├── lib/                        ← compiled JS output (tsc)
│   ├── package.json
│   └── tsconfig.json
├── backend_archive/                ← archived FastAPI backend (rollback only; gitignored)
├── MODEL/                          ← experimental / standalone risk-engine copy
│   └── athleteiq-risk-engine/
├── docs/
│   ├── repo_structure.md
│   └── wireframe.html.html         ← UI wireframe (single source of truth)
├── firebase.json                   ← points `functions` → `./functions`
├── firestore.rules
├── firestore.indexes.json
├── pubspec.yaml
├── AthleteIQ_Build_Guide.md        ← setup guide (repo root, not under docs/)
└── README.md
```

★ **Server-side codebases:**

| Path | Runtime | Role |
|------|---------|------|
| `functions/` | Node 20 + TypeScript | **Canonical backend** — referenced by `firebase.json`, deployed with `firebase deploy --only functions`. Includes risk engine + Phase E2 AI chat stub (`functions/src/aiChat.ts`). |
| `backend_archive/` | Python + FastAPI | **Archived rollback copy** (formerly `backend/`). Gitignored. Not part of active development. |
| `MODEL/athleteiq-risk-engine/` | Python | **Prototype / Render deploy** — third copy of the risk engine; treat as reference or experiment. |

## 3. Where Phase E Cloud Functions should go

For any phase that means “add or extend Firebase Cloud Functions” (including
**Phase E** risk triggers and **Phase E2** Ask AthleteIQ), work in:

```
functions/src/
```

Specifically:

- **Risk recalculation** → `functions/src/index.ts` (`recalculateRisk`)
- **Risk / ACWR math** → `functions/src/calculations.ts`
- **Risk classification** → `functions/src/riskModel.ts`
- **Recommendations** → `functions/src/recommendationEngine.ts`
- **Ask AthleteIQ (Phase E2)** → `functions/src/aiChat.ts` (stub ported from archived FastAPI backend)

Deploy with:

```bash
cd functions
npm install
npm run build
cd ..
firebase deploy --only functions
```

`backend_archive/` is a local rollback copy of the former FastAPI service
and is gitignored — do not develop against it.

`MODEL/athleteiq-risk-engine/` should not be the target for new Phase E
work unless you are explicitly working on the Render-deployed prototype.

## 4. Flutter app layout (detail)

```
lib/
├── main.dart                 # App entry, auth gate, debug routes
├── firebase_options.dart
├── dev/                      # Debug-only tooling (not shipped features)
├── models/                   # Data classes (Athlete, CheckIn, RiskResult, …)
├── screens/                  # Full-page UI (athlete + coach journeys)
├── services/                 # Auth, Firestore streams/writes
├── theme/                    # AppColors, AppTheme (Phase A)
└── widgets/                  # Shared components (Phase B)
```

Platform folders (`android/`, `ios/`, `web/`) are standard Flutter
scaffolding generated by `flutter create`; app logic stays in `lib/`.
